# 悬浮入口的位置存在客户端，不进插件配置

用户拖动悬浮入口后的位置，只存进浏览器 `localStorage`（键 `dsh-plugin-status-board.fab.v1`），**不新增插件配置项**。

三个理由，按权重排序：

1. **它是设备偏好，不是工作区策略。** 位置取决于这台机器的屏幕尺寸、窗口形状、外接显示器，换个环境就应当不同。配置项在本插件的模型里是"跟着工作区走"的东西（近期窗口、最大条数、默认折叠），把一个纯设备维度的值混进去，会让同一份配置在两台机器上互相打架。
2. **配置面被精确锁定。** `tests/config.test.ts` 用 `toEqual(CONFIG_DEFAULTS)` 全等断言四个键，`tests/host.test.ts` 对 Host 暴露的 shape 做 `Object.keys().sort()` 全等断言。新增一个配置键要同时改 schema、Host 路由、config 解析、patch 文件与这两处断言——为一项视觉偏好付这个代价不成比例。
3. **写入路径更短。** 位置只在客户端产生、只在客户端消费。走配置项意味着"客户端 → Host 写回 → 下次启动再读回"，跨进程往返一次，还引入写失败的错误处理分支。

## Consequences

- 位置不跨设备同步，也不跨浏览器共享；换机器需要重拖一次。这是刻意取舍。
- 清除站点数据会把位置一起清掉，回到默认位置——与"重置"等价，无需额外处理。
- 已存在的折叠状态用的是同一套 `localStorage` 机制（键 `dsh-plugin-status-board.collapse.v1`），两者互不影响、各自独立版本化。
